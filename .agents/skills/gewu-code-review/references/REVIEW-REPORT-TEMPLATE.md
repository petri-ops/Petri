# 评审报告模板

> 本模板自包含。形态约定：结论先行、表行式发现、每条三要素（位置/现象/建议）。

## 报告骨架

```markdown
# <对象> 评审报告（YYYY-MM-DD）

**评审范围**：<commit 范围 / 文件清单 / 模块面>
**评审维度**：本轮跑了哪几维（七维度全跑 / 跳过某维 + 原因）
**结论**：<可收口 / P1 修复后可收口 / 需重做> + 一句话总评

## 发现清单

| # | 严重度 | 位置 | 现象（引用合同原文/实际行为） | 建议修法 |
| --- | --- | --- | --- | --- |
| 1 | P1 | path/file.ts:42 | <文档说 X，源码实际 Y> | <具体改法> |
| 2 | P2 | ... | ... | ... |

## 严重度定义（勿改写）

- P1 必修：契约破坏 / 数据正确性 / 安全边界 / 生产路径回归——修复后方可收口
- P2 强烈建议：可靠性/性能/可维护性实质影响——登记候选留痕
- Minor / Nit：风格命名注释——不阻塞

## 收尾

- [ ] P1 全部修复并复验
- [ ] P2 登记去向（AUDIT-LOG 候选 / 后续包）
- [ ] 同类发现 ≥2 次的，已按 governance「回归→门禁」规则转化或登记转化任务
- [ ] 最小化五问已过（HK-02）：无未裁决的「多做」面（命中项已入发现清单）
```

## 填写纪律

- "现象"列必须引用源码合同原文或可复现行为，禁止"不够优雅""建议关注"式空话
- 证据不足的疑点写 ⏳ 待验证行，不冒充发现
- 评审报告本身入 AUDIT-LOG 引用的证据目录或评审工作包文档，不散落聊天记录
