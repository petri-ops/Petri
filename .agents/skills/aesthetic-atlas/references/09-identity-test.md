# Identity Test — 五个问题区分"自有世界"与" borrowed skin"

Run before shipping any identity-level visual change. A product's look is its own only if these answers are structural, not decorative.

## 1. Remove the logo test

Hide the logo/wordmark. Is the screen still recognizably this product? If recognition depends only on the mark, identity lives in decoration, not in structure, spacing, color relationship, or component vocabulary.

## 2. Product-truth test

Name the product's irreducible promise (e.g. local sovereignty, auditability, evidence self-certification). Show one visual decision that **embodies** that promise structurally. Example: an open ring (not closed) = not cloud-closed; one highlighted cell = evidence point among neutral context. If no such mapping exists, the visual is generic.

## 3. Borrowed-movement test

For each borrowed style element: name its art movement and the structural principle it expresses. Can you explain why that principle helps the user's task? If you can only say "it looks premium", refuse it.

## 4. Coherence across surfaces test

Do the work surface, empty state, error state, settings, and identity surface feel like one world under different light? Color script (film) applies: same skeleton, semantic accent changes. If each surface invents its own style, unity failed.

## 5. Non-copy test

Are brand marks, copy, illustrations, or whole-page layouts from a reference product absent? Is licensing/provenance recorded for any borrowed pattern? Does the change avoid new dependencies? Any "yes to copying" fails.

## Scoring

- 5/5 pass → identity is structural; proceed to rendered verification.
- 3–4 pass → fix the failing questions before implementation; record reasons.
- ≤2 pass → the change is a skin; restart from product truth and reference disciplines.

## Petri-specific addendum

When testing Petri Desktop: also verify the change is compatible with `docs/design-charter.md`, `petri-css-theme` (navy family, hover/selected separation, no raw colors), existing brand assets in `petri-logo-concepts_assets/`, user preferences (less text, harmonious layout, restrained columns, theme-color consistency), and that identity-level color/world changes remain `pending_user_ruling` until explicitly approved.
