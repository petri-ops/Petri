# 产品原则参考（自包含速查）

> 本文件自带全部内容，执行不要求读取任何外部文件。宿主仓库若存在 `AGENTS.md` / 治理类 skill，
> 冲突时以宿主为准——本文件定位是随包速查（2026-09-09 定稿），不是宿主真相的替代品。

## 1. 单一真相红线

任何事实只有一个 canonical 家：状态活在 canonical 文档（roadmap/handoff/registry/台账），流程与判据才允许固化进 skill/脚本/门禁。禁止第二份 active 文档宣称同一 truthDomain；脚本与文档聚合呈现事实时，必须自我声明为"呈现层，非真相源"。

## 2. 固化三判据（什么值得做成门禁/skill）

1. 重复出现 ≥2 次；
2. 违反的后果是隐性且滞后的（靠人记必然漏）；
3. 判据可以机械化。

三条全中才固化。**反面红线：状态类事实永不固化**——"当前 active 工作包是什么"只能进 canonical 文档，固化它等于制造文档漂移的自动化版本。

## 3. 回归 → 门禁转化

同类缺陷第二次出现（commit 修复 / 评审发现 / 实机验收抓获），必须转化为机械门禁项（定向测试 / harness 检查 / dev-verify flow），并把映射关系写进门禁自身。参考先例：非主窗口 chrome 控件回归 → 窗口系统实机检查；临时残留与死链 → hygiene:check。

## 4. Fail-closed 与证据优先

- 门禁不可静默降级：跳过必须显式标注 SKIPPED 并给原因，未跑/失败的门禁不得表述为通过。
- 证据优先于散文：状态声明以 Git/运行时/数据库/验收证据为准；验收断言不可编造（强制 marker 输出等手段防伪造）。
- 只读工具不代做处置：报告（hygiene/state）与执行（删除/提交）分离，处置由人裁决。

## 5. 定向验证最小充分

默认只跑与改动面相关的测试与门禁（impact-map 定向），全量留给发布前/CI；门禁与测试互补，互相不替代。范围收窄不确定时 fail-closed 升级，不静默漏测。

## 6. 阶段纪律（G0）

宿主仓库长期处于 G0 开发期：Provider/公证/GA/远程发布等 G1+ 事项不校验、不实现、不视为缺口、不写入收口笔录（一句「G0 开发期常态 · 不外推 packaged/Provider/GA」即可）。提前进入 G1+ 需用户显式裁决。
