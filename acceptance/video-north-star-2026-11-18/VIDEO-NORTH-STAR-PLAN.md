## 0. 为什么落档

用户明确了最终目标：

> 最终能够轻松生成视频，内容涵盖语音、科普素材和知识背景；当前的多维支持、API 全家桶等阶段性优化，都是为了让最终内容生成更简单便捷，直接交付可用结果，剩余部分交由人工处理。

本计划把该目标转成：

1. 一条可评估的“主题 → 可用视频”能力链；
2. 一份当前能力支持度结论；
3. 一条按价值排序的实施路线；
4. 一组可验收的阶段出口。

核心判断：

> Petri 已有较强的通用 Agent、工具编排、产物证据、3D 工程和部分影音能力；尚未形成“一键交付科普视频”的分镜、合成、事实校对与成片质检闭环。

## 2. 目标定义：什么叫“可用结果”

### 2.1 用户输入

最小输入：

- 一个科普主题；
- 目标受众；
- 期望时长；
- 横屏或竖屏；
- 可选风格、语言与特别要求。

系统应主动判断缺少但可合理默认的参数，不应把大量技术细节重新抛回给用户。付费调用、外部资料外发和不可逆操作仍按既有治理要求确认。

### 2.2 系统输出

首版至少交付：

1. `video.mp4`：可直接播放和下载；
2. `narration.wav`：旁白原文音频；
3. `subtitles.srt`：字幕；
4. `script.md`：讲稿；
5. `sources.md`：资料来源与访问信息；
6. `video-project.json`：可编辑的视频工程说明书；
7. `qa-report.json`：机器检查结果与人工终审留白；
8. `manifest.json`：产物清单、哈希、生成参数与血缘。

### 2.3 人工保留的部分

人工只做：

- 最终内容审美与表达取舍；
- 必要的科学专业判断；
- 付费、外部服务或高风险操作确认；
- 对机器无法确定的问题作显式裁决。

## 3. 当前能力支持度评估

支持度定义：

| 档位 | 含义 |
|---|---|
| 较好满足 | 已有真实能力和可核验证据，主链可直接复用 |
| 基本满足 | 主链可用，但有明确边界 |
| 部分满足 | 有零件或契约，仍需人工编排或补关键环节 |
| 未形成闭环 | 未见产品化实现，不能作为当前能力宣称 |

### 3.1 分层结论

| 能力层 | 支持度 | 已有能力 | 主要差距 |
|---|---|---|---|
| 通用 Agent 与编排 | 较好满足 | 规划、工具执行、长任务恢复、取消、工作流、审计 | 缺视频创作专用任务模板 |
| 资料研究 | 基本满足 | 搜索、网页抓取、知识库混合检索、OCR、文件输入、知识溯源 | 缺来源权威度/时效分级、论文专用入口、冲突识别 |
| 图片与视频理解 | 基本满足，有边界 | 图片理解、视频抽帧、关键帧送视觉模型 | 长视频时间轴、音轨联合理解、分段摘要不足 |
| 语音 | 部分满足 | ASR/TTS 工具、幂等音频落盘、成本计量 | 默认关、单一云商、两种声音、无时间戳、真实云调用未验证 |
| 图形与视觉素材 | 部分满足 | SVG、图表、Gen UI、图片产物、3D 静帧 | 无通用文生图适配器，素材授权链未闭环 |
| 3D 构建 | 工程基础较强，场景化部分满足 | SceneSpec、Blender、外部网格、灯光相机材质、装配、CAD、视觉 QA、导出、转盘视频、修订与血缘 | 面向科普分镜编排不足；复杂角色/自然世界/通用动画与仿真未形成闭环 |
| 视频输出 | 特定场景已满足 | 3D 序列帧、转盘 MP4、视频 viewer | 不是多镜头科普成片 |
| 通用剪辑与合成 | 未形成闭环 | 可复用 FFmpeg 发现、执行和审计经验 | 缺分镜时间轴、字幕、音画同步、混音、转场、通用合成器 |
| 科普精准性 | 有地基，缺质量闭环 | 来源标签、知识块溯源、源数据不可变、产物哈希与血缘 | 缺逐论断证据、数字单位复核、冲突提示、画面科学一致性检查 |
| 一键交付体验 | 未形成闭环 | 可从聊天入口发起任务 | 仍依赖 Agent 临时组合工具，缺稳定产品流程 |

### 3.2 一句话读法

> Petri 有“大脑、工具箱、档案柜”，但还缺“导演、剪辑师、事实校对员”。

## 4. 三个重点方向

## 4.1 3D 世界构建

### 已具备

- 参数化 SceneSpec 与白名单操作；
- 本地 Blender 无头构建与渲染；
- GLB/GLTF/STL/OBJ 等外部模型导入与预览；
- 相机、灯光、环境和 PBR 材质；
- 布尔、倒角、阵列、部分装配约束；
- STEP/IGES CAD 交换与线框表达；
- 多视角静帧、线稿和视觉辅助 QA；
- GLB、STL、OBJ、FBX、USDZ、STEP 等导出；
- 序列帧和转盘 MP4；
- 修订、洋葱皮对比、提案幽灵和血缘；
- 本地分享包。

适合场景：

- 机械结构与工程原理演示；
- 器械、装置、产品展示；
- 物体旋转与拆解说明；
- 科普视频中的局部三维镜头。

### 待优化

3D 能力目前偏“工具与对象”，还缺“镜头与叙事”的组织层：

> 这一段解释什么 → 需要哪些模型和动作 → 镜头怎么运动 → 与旁白如何对齐。

### 尚存缺口

- Tripo 文生 3D 只有契约、mock 和 UI 证据，真实服务未验证；
- 图生 3D 尚未正式接入；
- 复杂角色、自然世界、通用骨骼动画、粒子与物理仿真未见完整验收闭环；
- `sand3d`、`three-live`、`Polyfork`、`img2threejs` 仍属评估或待用户裁决；
- 新规划中的 Scene IR 必须先与现有 SceneSpec 对齐，禁止另起第二套场景真值。

### 结论

3D 是现有优势，但当前更偏“可信的三维物体与工程场景生产”，不是“任意 3D 科普世界自动生成”。它应作为视频中的可选镜头能力，而不是首条成片的阻塞前置。

---

## 4.2 影音生成

### 已具备

- ASR 和 TTS 工具；
- 音频按文本/声音/格式哈希幂等落盘；
- 图片和视频理解；
- 本地 FFmpeg 抽帧；
- Blender/FFmpeg 输出转盘 MP4；
- 视频结果预览和原文件导出。

### 关键边界

- 语音默认关闭；
- 当前仅 DeepSeek 云渠道；
- 仅 `stella` / `tide` 两种声音；
- 仅 WAV / PCM；
- 非流式；
- 无字词时间戳；
- 真实云调用为 `external-blocked` 证据状态。

尚未形成：

- 通用文生图；
- 文生视频、图生视频；
- 多镜头分镜时间轴；
- 自动字幕与音画同步；
- 背景音乐、响度归一化与混音；
- 转场、片头片尾、镜头运动；
- 通用视频合成器。

### 结论

当前是“能处理若干影音素材”，不是“能自动完成影音作品”。这是 P0 最高优先缺口。

---

## 4.3 科普内容精准构建

### 已有基础

- 搜索结果带 URL、主机名和来源信息；
- 网页访问、重定向链与成本可审计；
- 知识库可回溯到文档和知识块；
- OCR 与文件输入减少人工转录；
- 源数据不可变，派生产物保留哈希与血缘；
- Agent 有“不确定就说明、失败不冒充成功”的机制基础。

### 尚缺闭环

1. 来源权威度、发布时间和适用范围分级；
2. 论文、DOI、权威机构等专门资料入口；
3. 每个关键论断对应具体来源与原文片段；
4. 数字、单位、数量级与换算复核；
5. 不同来源冲突时的显式提示；
6. 画面、动画、三维模型是否错误表达科学概念的检查；
7. 低置信内容阻断或显著标注。

### 结论

现有能力让内容“更容易正确”，但不能保证正确。需要从检索增强升级为：

> 论断 → 来源 → 原文证据 → 讲稿 → 画面 → 检查结果的闭环。

## 5. 实施路线

## P0 · 科普视频最小成片闭环（最高优先）

### 目标

用现有 FFmpeg、TTS、SVG/图表与 Blender，先做一条可控、可审计、可修改的短视频；不追求最强的生成模型。

### 预置范围

- 30～60 秒；
- 3～5 个镜头；
- 固定一个画幅档位；
- 720p 起步，具备条件时提升到 1080p；
- 中文旁白；
- 自动字幕；
- 简单图形、图表或三维静帧；
- 来源清单与机器检查报告。

### 核心工作

1. **定义 VideoProjectSpec**
   - 目标、受众、时长、画幅、风格、语言；
   - 关键论断及来源；
   - 每个镜头的画面、旁白、素材、时长和字幕；
   - 音频、渲染、检查参数；
   - 产物哈希与证据引用。

2. **真实语音冒烟**
   - 用用户显式确认的真实 TTS 调用验证；
   - 先验证可生成可解码 WAV，再进入全链；
   - 云调用不可用时诚实失败，不用 mock 冒充。

3. **按镜头生成语音与字幕**
   - 一个镜头一段旁白；
   - 用 `ffprobe` 取音频时长；
   - 以镜头实际音频时长安排视频与字幕；
   - 首版不要求字级时间戳。

4. **新增通用视频合成窄口**
   - 建议名：`compose_video`；
   - 复用 FFmpeg 发现、执行、超时、取消、审计与成本模式；
   - 不把 `composeTurntable` 硬改成全能剪辑器；
   - 支持图片/静帧序列、镜头时长、字幕、音轨、基础转场与 H.264 输出；
   - 失败、缺工具、无素材、超时均返回结构化原因。

5. **产物清单与预览**
   - MP4、WAV、SRT、脚本、来源、工程文件、QA 报告统一登记；
   - 视频沿用有界 viewer；
   - 补基础音频试听能力；
   - 所有产物有 sha256 与来源血缘。

### P0 验收

- 真实模型/真实 TTS 在用户确认后可用；云不可用时诚实阻断；
- 输入一个主题后可生成完整 VideoProjectSpec；
- 输出视频可被 Chromium 和 ffprobe 解码；
- 分辨率、时长、帧率、音轨符合预设；
- 字幕时间与旁白一致且不越界；
- 无缺素材静默跳过、无黑帧冒充镜头；
- 至少一个关键论断可追到来源；
- 失败任务不生成“成功但不可用”的 MP4；
- 全部产物进入 artifact/manifest/hash 链。

### P0 非目标

- 不接通用文生视频；
- 不引入新 npm 运行时依赖；
- 不做复杂角色动画或物理仿真；
- 不做完整非线性视频编辑器；
- 不要求首版自动判断科学真伪，只要求记录来源与不确定性。

## P1 · 科学证据与质量闭环

### 目标

把“能查资料”升级为“每个关键说法都能解释从哪来”。

### 工作项

- 建立 Claim–Evidence 表；
- 来源分级：官方文档、论文、权威机构、普通网页、用户材料；
- 记录访问时间、发布日期、URL/DOI 与引用片段；
- 数字、单位、数量级和换算的确定性检查；
- 冲突来源并列展示，不由模型悄悄择一；
- 低置信或无来源论断显著标记；
- 画面、动画、三维镜头与讲稿的科学语义对照；
- 成片 AV 质检：黑帧、静音、响度、音画时长、字幕溢出、编码错误。

### 出口

- 随机抽查 5 个关键论断，均能定位来源原文；
- 至少一个数字/单位错误样本被机械或人工检查捕获；
- 一个冲突来源样本没有被静默合并；
- 一个故意注入的坏字幕/缺音轨样本被 QA 报告拦下。

---

## P2 · 素材供给与分镜审阅

### 工作项

- 可授权图片、视频、音乐素材搜索；
- 素材许可、署名和来源清单；
- 通用图像生成适配器（如新增服务，须先过依赖与隐私裁决）；
- 图表、SVG、Gen UI、3D 静帧统一为镜头来源；
- 音频试听与替换；
- 分镜稿结构化审阅；
- W11 Gen UI spec 引擎若已落地，可作为分镜卡渲染面，但不是前置依赖。

### 出口

- 一个镜头可替换素材而不破坏时长与字幕结构；
- 每个外部素材有授权状态和来源记录；
- 用户可在成片前看到并修改分镜清单；
- 默认不新增外部依赖；任何新增均须裁决。

---

## P3 · 高级镜头与 3D 世界

### 工作项

- 按镜头接入文生视频、图生视频；
- 复杂相机运动、角色动画、物理和粒子；
- 三源几何资产（程序化、现成件、图像重建）与 Scene IR 归一；
- 生成结果的质量门禁、失败降级与证据链；
- 高成本镜头的缓存、重试和版本比较。

### 前置

- 3D 依赖与授权裁决完成；
- 新 Scene IR 与既有 SceneSpec 的映射关系明确；
- 生成服务成本、隐私和外发边界明确；
- 不触碰 Result Studio 资格线与 G0 阶段纪律。

### 出口

- 至少证明一个高级镜头可替换普通镜头而不改视频工程主干；
- 换 producer / 换 renderer / 加领域三类可替换判据在 3D 域内保持；
- 所有生成镜头均有来源、参数和验证证据。

## 6. 数据模型初稿

`VideoProjectSpec` 至少包含：

```text
VideoProjectSpec {
  schemaVersion
  goal: { topic, audience, language, durationSec, aspectRatio, style }
  claims: [
    { id, text, sourceIds, confidence, checks, uncertaintyNote }
  ]
  sources: [
    { id, kind, urlOrPath, title, accessedAt, publishedAt, license, excerptRef }
  ]
  scenes: [
    {
      id,
      durationSec,
      narration,
      captions: [{ startMs, endMs, text }],
      visual: { kind, specRef, assetRefs, camera, motions },
      evidenceRefs: [claimId]
    }
  ]
  audio: { voice, format, narrationRefs, music }
  render: { width, height, fps, codec, container, transitions }
  qa: { checks, status, reasons, humanReview }
  lineage: { conversationId, toolJobs, artifactIds, hashes }
}
```

约束：

- `VideoProjectSpec` 是成片的可编辑工程说明，不替代既有 artifact truth；
- 素材和场景真值仍以工作区文件、SceneSpec 与 manifest 为准；
- spec 变更须可 diff、可哈希、可追溯；
- 不使用第二套 Job、Artifact 或执行器。

## 7. 依赖与风险

| 风险 | 处置 |
|---|---|
| 真实 TTS 不可用或收费 | 首次调用显式 P5-a 确认；失败诚实，不 mock 冒充 |
| FFmpeg 缺失或不可用 | 复用现有探测；缺工具返回 `capability_unavailable`，不下载 |
| 画面素材授权不清 | 默认只用本地生成/用户材料；外部素材需授权记录 |
| 科学内容幻觉 | Claim–Evidence 表；低置信标记；不把检索等同事实保证 |
| 字幕与音画不同步 | 按镜头音频实际时长排程； ffprobe 校验 |
| 生成式视频风格不一致 | 先做确定性镜头；生成镜头只作单点替换 |
| 3D Scene IR 与 SceneSpec 冲突 | 开工前先做映射探针；不建第二场景真相 |
| 新依赖膨胀 | 默认零新增；新增须过 DEPENDENCY-CHANGE-CHECKLIST |
| 一键体验吞噬治理 | 付费/外发/高风险确认保留；审计层默认收起但可查 |

## 9. 完成语义

- 本计划落档完成 ≠ 视频能力完成；
- P0 `completed` 必须有可解码成片、来源、字幕、工程文件、QA 报告和实机证据；
- 云 TTS 未验证时只能标 `external-blocked`，不得写 verified；
- 观感和科学专业性终审由用户或明确授权的专业人员签字，Agent 不代签；
- 高级 3D、生成式视频、通用文生图均按各自阶段裁决，不在 P0 外推。
