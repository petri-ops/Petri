## §5 本轮实测暴露的问题（评估的核心，不是台账复述）

### 5.1 P1：上下文压缩破坏 tool 消息配对（C-45，未修）

- 证据：`core/petri-server/helpers/message-trimmer.js:159-160`，`pickWithinBudget/scoreMessages` 按打分贪心拾取，**无 tool 链配对约束**；可裁掉 `assistant(tool_calls)` 而保留下属 `tool` 消息 → 后续请求被 provider 整体 400 → 长任务中断。
- 实锤：BLOCK-348 的 T7（30+ 步长任务）因此阻断，是 8 个任务里唯一「能力在但做不完」的失败。
- 348 报告判词：**「最大短板是韧性而非能力」**。
- 影响：小窗口 / 高压力长任务不可靠；直接压低自主完成率上限。

### 5.2 P1（门禁）：`quality:perf` 稳定红，closeout 当前 FAIL

- 当次复跑：`long_conversation` 样本 **36ms / 34ms**，基线中位 **20ms**，阈值 `20×(1+60%)=32ms` → 红；另三场景绿。
- **两次复跑一致**，非偶发抖动。
- 判定：**不是产品性能退化**（34ms 仍属毫秒级），是**门槛设计问题**——低耗时场景（12–20ms）用纯百分比容差，任何系统负载都能造成 60%+ 相对波动。
- 更重要的方法论问题：台账写「closeout 16 门全绿」是**收口时点采样**；门禁应具备**持续可过**的能力，否则「全绿」不构成事实。

### 5.3 P1：垂直能力硬伤（C-46）

- `plugins/deseq2/scripts/deseq2.R:72-73` 跨行字符串常量（R 无隐式拼接）→ **任何 deseq2 运行必失败**；pack 0.2.x 交付未回流兄弟仓 latest。
- 由 349 实机腿意外发现，说明「实机验证」的价值正在兑现，但也说明此前该能力从未真跑过。
