## 1. 目标与发布边界

本计划用于把当前开发快照收口为第一个可安装、可验证、可追踪的 Release Candidate。RC 用于验证完整产品链路，不等同于稳定正式版。

必须区分三个状态：

1. **RC 准备中**：版本字段已设置，但源码、依赖或安装验证尚未全部通过。
2. **RC 可打标签**：所有强制门禁通过，发布 commit 可复现且工作树干净。
3. **RC 已发布**：标签、安装包、校验和、发布说明和回滚信息均已上传并验证。

在第 2 状态之前，禁止创建 `v0.0.1-rc.1` 标签；在第 3 状态之前，禁止向自动更新源推送该版本。

## 2. 发布不变量

- 唯一正式执行事实链保持为 `run_tool → tool_job → artifact truth`。
- Core 必须先形成独立、已推送的干净 commit；Desktop 再同步 submodule 指针和 `.vendor-lock`。
- 发布安装包必须能由一个 Desktop Git commit 和一个固定 Core commit 重建。
- 正式分析不得绕过参数确认、artifact truth、lineage 和恢复审计。
- 报告是后置交付物；核心 artifacts 仍是结果查看和后续分析入口。
- 任何测试、签名、安全或安装阻断都不得通过“先发版后修复”跳过。
