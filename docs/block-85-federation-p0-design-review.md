## 1. 目标一句话

两台桌面各自跑着格物；两个格物**软件实例**之间通过格物自己的协议（配对 + 会话 + HTTP API）互派任务——Windows 格物可以把分析作业/Agent 工作委托给 Mac 格物，Mac 用它自己的本地执行器跑完把结果回流；反向对称。全程不碰对方的系统 shell。

## 3. 设计裁决点（D1–D8）

### D1 联邦通道形态
对端格物的协作端点 = **复用 mobile-gateway 实例**（同一配对/会话体系），新增 `/federation/*` 路由组；不做第二个 gateway。**建议：是**——一个端点服务手机+对端格物两类客户端，权限同源。

### D2 配对方式
对端格物如何配对：指挥席生成配对二维码/URL（现有面板加「协作节点」页签）→ 在对端格物的协作面板输入/扫码 → 走现有 `/pair` 兑换会话。对端格物保存会话 token（只存 hash，同现有）。**建议：沿用，零新机制**。

### D3 分析作业级协议（任务粒度 1）
指挥席把作业 POST 到对端 `/api/tools/run`（对端以本地身份跑自己的 tools-executor）→ 作业状态经 SSE 回传指挥席 → 完成后产物（PNG/表格）由指挥席按需拉取（对端已有文件读取面）。指挥席本地落一条镜像 job（状态投影，真值在对端）。**建议：此形态**——对端跑的作业在对端也有完整记录（Artifact Truth 留在对端），指挥席是视图。

### D4 Agent 会话级协议（任务粒度 2）
指挥席 agent 新工具 `delegate_to_gewu_node`（参数：节点+任务描述）→ 对端 `POST /api/ai/agent` 开新会话执行 → 流式回传摘要与进度 → 终态（含关键产物引用）回指挥席会话。**建议：此形态**——对端 agent 是完整独立会话（对端可查），指挥席看到的是委托单+回执。

### D5 执行位置 UI
工具提交卡执行位置现两态（本地/远程目标）→ 加第三态「格物节点」，列出已配对在线的对端格物（名称+机型+在线状态）。**建议：并列第三态，不混入 SSH 目标列表**。

### D6 安全边界
配对+会话+吊销+审计全复用；联邦会话 scope 两档：`jobs`（只跑作业）/ `full`（作业+agent 委托）。默认 `jobs`。对端面板可见全部联邦会话并即时吊销（同手机面板体验）。**建议：默认 jobs，用户配对时选档**。

### D7 断线语义
对端离线：指挥席侧任务标记 `node_offline`（挂起不丢）；对端恢复后继续跑并回传终态（对端本地 DB 是任务真值，指挥席是投影——投影断或错不污染真值）。**建议：挂起+回填**。

### D8 双向对称
两端代码完全相同（同一份 main 分支），互为指挥席/执行端；一个包双向交付，不存在"服务端版本/客户端版本"。**建议：是**。

## 4. 风险登记

1. **Artifact 跨实例**：产物真值在对端，指挥席是投影——D3 形态已把污染面隔离（投影只读）。
2. **长作业 + 指挥席关闭**：回传断；对端任务照跑，指挥席重开后按任务列表对账回填。
3. **版本漂移**：两端格物版本不同时的协议兼容——协议面小（配对+3 端点），P1 时加最低版本握手，不匹配诚实拒绝。
4. **执行器差异**：对端没装 R/Python 时作业诚实失败（对端已有 runtime preflight）。

## 6. 非范围

不做系统级控制（SSH/键鼠/桌面投影复用）；不做文件系统级同步（文件随任务走）；不做多于两台的中继拓扑（P5 候选）；Bot Channel/Web Push（BLOCK-70 P5 候选不变）。
