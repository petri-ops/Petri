# 下一阶段端到端执行计划（批量裁决优化版 · 2026-11-17）

> 发令：用户 2026-11-17「起草一份新的端到端提示词，明确区分『可预置自动执行』与『必须由我签字或裁决』的边界，严格避免越过『观感不代签』的红线……将需要人工裁决的事项集中处理：先自动推进所有可预置的部分，再把待裁决内容汇总成批次统一提交，减少反复打断」。
> 性质：执行计划（reference / planned）——把 C-54 六档序列的下一阶段工作按 A/B/C 三分类重组，配套 `docs/next-phase-e2e-prompt-2026-11-17.md`（自包含提示词入口）。
> 顶层依据：`docs/petri-master-charter.md`；冲突以 charter 与对应 canonical 为准。G0 开发期常态 · 不外推 packaged/Provider/GA。

## 0. 相对上一版 E2E 的优化点

| 维度 | 上一版（E2E-PROMPT / execution-plan） | 本版（批量裁决） |
|---|---|---|
| 裁决处理 | 全部 D1–D8 预置为默认值，运行时不再问 | **三分类**：A 自动 / B 集中批 / C 立即停 |
| 用户打断 | 仅"未预置新裁决点"才停 | A 段全跑完攒批 → **一次**提交全部 B 类 → 一次批复 |
| 观感处理 | D8 标"待用户确认不代签" | B 类硬判定 + 三处红线，**观感永不进"可代签"选项** |

## 1. 自动化前置条件（硬门，任一不满足停在起点）

- AUDIT-LOG 无 🔴 阻塞；active 串行包为空或已明确归属；
- 工作区无未知他方 WIP；HEAD 与恢复基线一致；
- canonical 可读：petri-master-charter、SUPER-BLUEPRINT（C-54）、next-work-blueprint、3D dependency-ruling、gen-ui evaluation；
- 环境：Node 24（fnm）、Git Bash PATH 前置、dev-infra 启动纪律。

## 2. 三分类判定表（每步先分类）

| 类别 | 判定标准（命中任一即归入，A 需全部满足） | 动作 |
|---|---|---|
| **A 自动** | 无观感判断 ∧ 不涉用户资产 ∧ 不引依赖/不改默认/不改 manifest ∧ 失败可诚实降级 ∧ 有明确默认口径 | 直接执行，边跑边收集 B 项 |
| **B 裁决** | 观感验收 / 外部依赖引入 / 用户资产处置 / 授权红线 / 方向性选择 | 不自动做，攒入批次，绝不代答代签 |
| **C 停止** | 安全红线 / 破坏性操作 / 数据丢失风险 / 超授权新裁决点 | 立即停，报告，不进批次 |

## 3. A 类任务卡（自动段 · 七字段）

### W-1 · 后台失败任务对账
- **输入**：`npm run task:status` 的 4 条失败任务（vite-ui701 / build-win-v003 ×3）。
- **步骤**：①核对每条日志尾部与 exit code → ②确认是否已有 exit=0 继任或属已解决问题的过程产物 → ③登记清账结论（不删日志）。
- **交付物**：对账记录（acceptance/ 或 AUDIT-LOG 指向）。
- **依赖**：无（自动段队首）。
- **门禁**：无产品门禁；如实登记即可。
- **验收**：4 条均有结论；不伪造成功；不删除用户数据。
- **失败分支**：日志缺失/结论不明 → 标"待核"，不擅自判成功。

### W-2 · 状态与 canonical 复核
- **输入**：`npm run state`、docs:check 输出、AUDIT-LOG 头部、charter §4 工作面索引。
- **步骤**：①现读 state → ②核对 charter §4 五类工作面与实际一致 → ③docs:check 确认仅剩既有 post-h9 红 → ④记录复核结论。
- **交付物**：复核记录 + 若有漂移的修正建议（不擅自改 charter 冻结项）。
- **依赖**：W-1。
- **门禁**：docs:check（允许既有红）。
- **验收**：charter §4 索引与现读一致；post-h9 红如实标注 D5 待用户处置。
- **失败分支**：发现新漂移 → 记入 B 批次，不自动改 canonical。

### W-3 · 只读探针与材料核实
- **输入**：3D dependency-ruling、IMG2THREEJS-EVALUATION、sand3d/three-live 调研。
- **步骤**：①在不装依赖前提下，能做的只读核实（文档/已有物料）→ ②输出探针报告草案 → ③若某子项（如 GLB extras 实测）必须装包才能做，**改列 B 类**，不擅自装。
- **交付物**：探针报告草案（acceptance/）。
- **依赖**：W-2。
- **门禁**：无（只读）。
- **验收**：零安装、零 manifest 改动；需装包项已转入 B 批次。
- **失败分支**：无可用物料 → 标 external-blocked，不硬造数据。

> A 类全部收口后，进入阶段 2（集中裁决）。

## 5. 集中裁决触发时机

1. **主触发**：所有 A 类任务收口且有当前证据；
2. **备触发**：A 类已做完、继续推进必须等待 B 类裁决（无其它可自动项）；
3. **不得零散打断**：A 类执行中遇到 B 类只收集、不中途提问；等批次统一提交；
4. **C 类例外**：立即停，不受"攒批"约束——保护优先于减少打断。

## 6. 依赖图与风险

```text
A(W-1 对账) → A(W-2 复核) → A(W-3 只读探针)
      ↓（全部 A 收口）
集中裁决批次 B-1..B-10 → 用户一次性批复
      ↓（按批复）
B8 发令且 B6/B7 定 → W11 P0-P2（工程包，占串行槽）
B1..B5 定 → 3D P0 探针 → P1 首包（裁决+探针后，占槽）
B9/B10 → 用户动作，不阻塞已批复工程包
```

| 风险 | 处置 |
|---|---|
| 批次过大用户裁决负担 | 每项固定字段 + 推荐 + 一次性批复模板；观感项不混入选项 |
| B 类未裁决被偷偷执行 | A 类判定硬约束 + 越权红线 + 未批复不开包不装依赖 |
| 观感被代签 | B 类判定第 1 条 + 批次单"不提供代签选项" + 验收零代签 |
| C 类被"批量"吞掉 | C 类立即停，优先于攒批 |
| 探针被迫装依赖 | 转 B 类，不擅自装 |

## 7. 验收与回退

### 7.1 验收标准
- A 类：任务卡七字段全执行或有 external-blocked 标注；门禁绿；证据在册；回写完成；
- B 类：全部进批次单、零代答；观感项零代签；批复原话与日期在册；
- 整体：`npm run state` 可恢复、无未决 WIP 混淆；docs:check 仅剩既有红；自动段状态=「完成 + 待裁决」不冒充"全部完成"。

### 7.2 回退规则
- 契约抓不到 / 文档 404 → 标 UNVERIFIED + external-blocked，降级或跳过子步；
- 无 key / 无样本 → 契约级证据 + external-blocked，不伪造实机；
- 测试红 → 先归因（本包 vs 存量）再修，不改基线掩盖；
- 用户批复与推荐冲突 → 用户裁决优先，按批复执行并留痕；
- 批复后发现触及 charter 冻结项 → 停下，走 charter §5 变更评估，不直接执行。

## 8. 完成语义

- **自动段完成**：A 类全收口 + 批次单输出 + 回写完成 → 停，等批复（不是整体完成）；
- **整体完成**：B 类批复 + 裁决后工程包按批复收口 + 观感项如实保留签字槽 + 最终报告（六件套交付物）输出；
- 最终报告结构见提示词 §7：自动段成果 / 裁决批次单 / 未执行项 / external-blocked / 回写记录 / 下一步提示。
