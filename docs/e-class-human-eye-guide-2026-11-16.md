## 2. 现在可过的 3 条（打开软件，逐条走）

### 2.1 UI-695 · 模型快捷配置 + run 级折叠（**最值得过**）

**打开路径**：主窗 → 新建/打开一个会话 → 看聊天输入框（composer）附近的模型菜单。

**观察点与判断标准**：

1. **模型快捷配置**：点开模型菜单，看是否出现「上下文窗口 / 思考强度」就地切换项。
   - ✅ 通过：能看到这两项；选「上下文窗口」某档（32K/64K/128K/200K）后写回当前模型档案，下一请求用新档；思考强度切换与既有 composer 按钮同源。
   - ❌ 不通过：菜单无这两项 / 切换后请求未生效 / 设置页与输入框两处显示不一致。
2. **run 级折叠**：发一条会跑多轮工具的任务（例如"列出当前目录并读 package.json 再总结"），观察工具行折叠。
   - ✅ 通过：本轮 run 内工具行统一展开，run 结束后统一折叠；历史轮次不因本轮 run 炸开（旧消息保持折叠）。
   - ❌ 不通过：跑的过程中逐条折叠 / 历史消息被本轮撑开。

**证据留存**：模型菜单切换前后各一张截图 `acceptance/human-eye-2026-11-16/UI-695-modelcfg-{before,after}.png`；多轮 run 中/后各一张 `UI-695-collapse-{running,done}.png` + 一句结论。

**我的判断建议**：代码侧 6/6 + 邻域 20/20 已绿，风险只在观感与"下一请求生效"，你按上面 4 步走基本能一次过。**若通过→你在台账 UI-695 写 verified；若发现逐轮折叠/历史炸开→记现象，属真实缺陷需另开修复。**

### 2.2 UI-200 · Working Tree Review CodeMirror 升级

**打开路径**：主窗 → 进入一个 git 项目工作区 → 打开"工作树评审 / ReviewMode"面板 → 看 diff 渲染区。

**观察点与判断标准**：

1. diff 代码区是否用 CodeMirror 渲染（语法高亮、行号、可滚动）。
   - ✅ 通过：高亮正确、行号对齐、长文件滚动流畅、亮/暗主题都正常。
   - ❌ 不通过：高亮错乱 / 行号错位 / 暗色不可读 / 滚动卡顿。
2. 评审操作（逐 hunk 接受/拒绝）是否仍可用。

**证据留存**：亮/暗各一张 diff 区截图 `UI-200-diff-{light,dark}.png`。

**我的判断建议**：组件测试 8/8 + production 已接线，主要看观感与暗色对比。**通过→台账翻 verified；有问题→记现象。**

**打开路径**：主窗 → 看左栏会话列表的时间显示。
