> 定位：本文件是 3D 造物域的**稳定顶层设计（canonical charter）**，长期有效、不随阶段方案漂移。它与"可变的分阶段实施层"物理分离——后者可随裁决、探针、阶段进展调整，但不得违背本文件。

> 冲突规则：**任何 3D 相关分阶段方案、依赖裁决、超级蓝图投影与本文件不一致时，以本文件为准**，并在同批修正派生文档。

## 1. 核心目标（稳定 · 冻结）

1. **把 3D 创造从"散点 Skill/工具堆砌"升级为领域无关的"造物域"**：按 Petri 既有领域入驻配方（工具包 + Skill 包 + viewer 包，内核零改动）组织，成为可复用、可审计、可替换的生产线。
2. **建立统一 Scene IR 为解耦枢纽**：三源几何归一到同一中间表示，上游换几何来源、下游换渲染引擎都不动其它层。
3. **形成三源几何来源闭环**：来源 A 程序化建模（sand3d）、来源 B 现成素材（Polyfork）、来源 C 图像重建（img2threejs），覆盖"工程件 / 现成件 / 图生件"三类创作入口。
4. **建立证据自证闭环**：生成物经静态诊断 → 视觉对照 → 仿真 → 可动性验证，证据写入 artifact truth 链，可 sha256 复现。
5. **落 Petri 的魂、不动通用主线**：命中本地主权 / 证据自证 / 治理透明 / 场景锚四个差异化锚点；**不触及 dim1 推理 / dim2 记忆 / dim3 编排的通用 agent 主线**。

> 这五条是方向的"北极星"。阶段方案可以增加能力，但不得偏离或删除这五条。

## 2. 范围边界（稳定 · 冻结）

### 2.1 范围内（in scope）

- L0 意图编排 / L1 几何生产 / L2 Scene IR / L3 呈现 / L4 验证证据 五层架构 + L5 治理扩展（横切）；
- 三源几何来源及其到 Scene IR 的归一；
- 领域包 catalog 扩展点（领域零内核改动放大能力）；
- 与 Gen UI、MCP 货架、viewer registry、artifact truth 链的既有插座对接。

### 2.2 范围外（out of scope · 明确排除）

| 排除项 | 原因 |
|---|---|
| 自研通用 3D 引擎 / 神经文生 3D | 非 Petri 主线；复刻通用形态即失魂 |
| 把 3D 引擎引进前端渲染进程 | 违反架构边界（沙箱/外部 server 呈现） |
| 把素材/模型打包进产品分发、对外生成服务 | 授权红线（Polyfork 禁令）+ 本地主权 |
| 通用低代码平台 / 预设未来领域组件 | 范围蔓延（沿 artifact-plane 反目标） |
| 触碰 Result Studio 资格线（implemented_unverified / RS-P7 deferred） | 资格语义不动 |
| 任何 G1+（Provider / 公证 / GA / 远程发布） | G0 开发期纪律 |

## 3. 关键原则（稳定 · 冻结）

1. **内核零改动判据**：任何新几何来源 / 渲染器 / 领域入驻，若需改内核即设计证伪，触发 reopen（继承 `artifact-plane-direction.md`）。
2. **Scene IR 枢纽原则**：L1 只生产 IR、L3/L4 只消费 IR；禁止跨层直连，禁止第二套中间表示。
3. **脚本 enforce / 模型 judge + fail-closed**：机械校验交给确定性脚本，模型只做视觉/语义判断；校验失败阻断产出并留痕，不静默降级（继承 img2threejs 门禁范式）。
4. **能力默认关 + 审批分层**：capability 默认关闭、显式开启；建模程序执行走 guard-ack 审批链，不建第二通道。
5. **证据即能力**：每次生成产物附验证证据（诊断/对照/仿真/可动性），落 truth 链；观感类一律 `pending_human_eye`，Agent 不代签。
6. **三源并存、不偏废**：来源 A/B/C 均纳入实施范围，不得因某一源更易实现而退化（如退化为"素材浏览器"）。
7. **文本资产优先**：产物尽量为可 diff、可版本控制的文本（spec / factory / JSON），而非仅大型二进制网格。

## 4. 约束条件（稳定 · 冻结）

| 约束 | 内容 |
|---|---|
| 阶段纪律 | G0 长期开发期；单工作包串行；一次只开一个 active 包 |
| 依赖纪律 | 零新增产品依赖优先；外部工具（sand3d/three-live/Polyfork/img2threejs）均需用户显式裁决，未裁决前不安装、不引包、不改 manifest |
| 本地主权 | 外部 AI 服务 / hosted 管线（TRELLIS、Context7 等）默认关，需用户裁决 + P5-a 确认；产物不出本机 |
| 授权合规 | Polyfork `.mjs`/HD 禁再分发、禁对外生成服务；外部素材授权边界须在裁决材料核清 |
| 资源有界 | 遵守 sandbox quotas；widgetState ≤16KiB；大资产分块/懒加载 |
| 证据等级 | dev Electron / packaged 边界内 verified 为当前阶段最高证据；不外推 Provider/GA |
| 治理门禁 | docs:check / ui:audit:check / skills:check / closeout 按改动域定向执行；观感不代签 |

## 5. 稳定性要求与变更评估（核心契约）

### 5.1 哪些部分不可随意变更（冻结项）

以下为**冻结项**——任何 Agent 不得因阶段便利、实现难度或模型偏好而改动；变更只能由用户显式裁决触发：

- §1 五条核心目标（尤其"不动通用主线""Scene IR 枢纽"）；
- §2 范围边界，特别是 §2.2 全部排除项；
- §3 七条关键原则（尤其"内核零改动判据""fail-closed""三源并存"）；
- §4 全部约束条件（阶段纪律、依赖纪律、本地主权、授权合规）；
- 本 §5 变更评估流程本身。

### 5.2 变更需经何种评估（变更流程）

任何对冻结项的修订，必须**全部**满足以下六步，缺一不可：

1. **触发条件明确**：仅限三类——① 技术证伪（P0 探针证明某源/映射不可行）；② 用户需求裁决变更；③ 治理/授权冲突（如依赖红线变化）。"实现更方便""阶段性简化"不构成触发条件。
2. **影响面评估**：书面说明改动影响哪几条冻结项、哪些派生文档需同步、是否触及内核 / 通用主线 / 资格线。
3. **依赖与授权复评**：若涉及外部工具，重跑 DEPENDENCY-CHANGE-CHECKLIST 四问与授权红线核对。
4. **用户显式裁决**：保留用户裁决原话与日期；Agent 不代答。
5. **三件套回写**：登记 DOC-REGISTRY / README 入口 / AUDIT-LOG 一行；派生文档（blueprint / 裁决材料 / 超级蓝图投影）同批对齐。
6. **版本留痕**：在本文件"修订记录"（§7）追加版本号、日期、变更摘要、证据位置；旧版结论不覆盖、不删除。

### 5.3 派生层如何保持与顶层一致

- 每份派生文档头部须声明"本文件从属于 `3d-authoring-domain-charter`，冲突以 charter 为准"；
- 派生文档收口时须自查 §1–§4 冻结项未被偏离，并在证据中记录该自查；
- 超级总蓝图 C-54 是 non-canonical 投影，其第 1/3 档 3D 排序仅执行投影，不得反向改写本文件。
