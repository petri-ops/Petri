# BLOCK-213 · 功能发现率

立项发令：2026-10-18「开 不过再次强调一下 启动软件的时候 不要用TEST有窗口的状态」（同轮授权 BLOCK-213，承接我上一轮建议二）。

## 0. 为什么是这个包

评估报告原判词是「**功能发现率 2.5~3/5**」——这不是债，是**产品差距**：能力有、入口少、用户找不到。这类问题没法靠"再写一个功能"解决，只能靠**把已有能力变得可发现**，而它的好处是**可数**：动作总数、面板可发现数、带快捷键提示的按钮数、有空态引导的页数。

## 1. 三条红线

- **只补入口，不造能力**：接进命令面板的必须已存在且幂等；新能力一律不在本包。
- **单一注册点**：命令定义只有一处（`COMMAND_DEFS`），热键只有一处；两处文案漂移由测试抓。
- **不偷偷删**：未接入的动作要进"不在面板"清单，不能为了好看从统计里删掉。

## 2. P0 要产出的四个数字（本项目第一次量）

1. 命令面板已注册动作数；
2. 可执行动作候选总数（导航项 + 主要按钮 + 设置分区）；
3. 带快捷键可见标注的控件数；
4. 有空态引导的页面数（目标 4：首页/结果/技能/知识库）。
