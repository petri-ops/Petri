# 设置页信息架构精简设计（IA Simplification Design）

> 性质：规划产物（设计材料）——**本文件不含代码实现**；输出调整后的设置项清单与分组说明，供用户裁决后另立 UI 工作包实施。
> 日期：2026-11-16。触发：用户「保留现有布局结构，全面梳理并精简信息架构；低频繁杂内容归纳/折叠/移除，突出高频核心项；输出调整后清单与分组说明，与下一阶段蓝图一致」。
> 现状基线：`frontend/src/components/desktop/DesktopSettingsPanel/types.ts` 的 `SETTINGS_SECTIONS`（13 组，9 core + 4 advanced，BLOCK-424 已做过一次 core/advanced 分层）；主组件 `DesktopSettingsPanel.tsx` + `sections/` 目录 40+ 面板。
> 蓝图对齐：BLOCK-454（通用能力窄口 + DeepSeek adapter，见 `docs/block-454-capability-adapters-plan.md`）将新增搜索/视觉/OCR adapter 等设置项——本设计预留其落点，避免下次再散落。

## 一、现状问题诊断（基于代码事实）

| 问题 | 证据 | 影响 |
|---|---|---|
| **配置能力分散且命名混** | `general` 节 = `ExternalImportPanel`（从外部 Agent 导入，BLOCK-264）；`maintenance` 节 = `ConfigTransferPanel`（自家配置 JSON 导出/导入备份）——两个不同面板、都属"配置迁移"，分在两节 | 用户找导入/备份要翻两处 |
| **低频项占 core 首位区** | `keymap`（快捷键）、`general`（配置迁移）标 `core`，但属配置一次即走；BLOCK-424 注释自承 `decisions`=29 输入/118 下拉/9152 字符、`diagnostics`=8846 字符，绝大多数用户不关注 | 高频项被淹没 |
| **繁杂节无内部折叠** | `compute` 节并列 RemoteTargets + DataManagement + HarnessEnvironment + TrashManagement 四块；`maintenance` 并列反馈/更新/日志/配置迁移；`usage` 三块 | 一屏信息过载 |
| **高级组命名不统一** | `decisions` 叫"决策原语"却含 Agent 规则/工具审批/记忆治理/运行时策略/审批记录 6 面板 | 名实不符，难查找 |
| **文档过载（本轮已治）** | UI-699 已精简 API Endpoint 区表头列名与说明文案 | 本设计延续该原则 |

## 二、调整原则（保留布局结构）

1. **布局形态不变**：仍是「左栏分组导航 + 右栏内容」+ core/advanced 两级折叠组，深链 `?section=` 继续有效——不改骨架。
2. **不删功能、只重组呈现**：所有现有设置项保留；"移除"仅指重复渲染与已死面（历史 UI-355 已移除的计算执行卡不再列）。
3. **高频上浮、低频折叠**：按使用频率重排 core/advanced 归属；繁杂节内部用折叠（`<details>` 或现有 SettingsField 分组）分层，默认收起低频子块。
4. **语义归位**：相近功能合并到同一分组，名称与内容一致。
5. **蓝图预留**：为 BLOCK-454 的 adapter 设置（搜索/OCR/视觉渠道选择）预留落点，纳入 models 分组的折叠子块。

## 三、调整后的分组清单（13 组 → 11 组）

> 稳定性优先：保留现有 13 个 `SettingsSection` id 中的 11 个不变（深链兼容），仅做**合并 2 组 + tier 重排 + 内部折叠**；不新增 id、不改路由。

### 第一层 · 常用（core，7 组，默认展开）

| # | 分组(id) | 名称 | 保留/调整 | 内部设置项（高→低频） |
|---|---|---|---|---|
| 1 | `appearance` | 外观 | 保留 | 主题、字号、主题色、动效（均高频，保持） |
| 2 | `desktop` | 通知与桌面 | 保留 | 通知、托盘、免打扰、关窗行为 |
| 3 | `models` | 模型与接口 ⭐ | **重点扩充** | **常用**：默认模型/生成偏好/API Endpoint（URL·Key·模型·上下文）<br>**折叠「能力渠道」**（BLOCK-454 落点）：视觉渠道绑定（P1）、搜索 adapter（P2）、OCR/文件解析（P3-P4）、Responses 协议（P5，可选）——按阶段逐步出现<br>**折叠「自动容错」**：备用模型链 |
| 4 | `network` | 联网与代理 | 保留 | 出网代理、自签证书、联网检索授权 |

| # | 分组(id) | 名称 | 保留/调整 | 内部设置项 |
|---|---|---|---|---|
| 8 | `decisions` | 治理与决策 | **改名+内部折叠** | 折叠三组：①「规则与审批」Agent 规则 / 工具审批 / 记忆治理；②「决策阈值」决策原语配置 / 运行时策略；③「审计记录」审批历史(GuardAck) |

| 10 | `diagnostics` | 运行时与诊断 | 保留 | 本地服务进程、运行时状态、日志 |
| 11 | `experimental` | 实验特性 | 保留 | 实验开关（长任务类已默认开） |

### 合并处理（13 → 11 的来源）

- **`general`（配置迁移，ExternalImportPanel：从外部 Agent 导入）** 与 **`maintenance` 中的 ConfigTransferPanel（自家配置备份）** 语义相近、都低频。方案：**取消独立 `general` 分组**，两个面板合并进 `maintenance`→「更新与备份」的折叠子块「导入与备份」（外部导入 + 自家备份并列，各自小标题）。
  - 深链兼容：`?section=general` 重定向到 `maintenance`（保留一个映射，避免旧链接失效）。
  - 注：这是本设计唯一的分组数变化；若用户要求"分组数绝对不变"，可退化为保留 `general` 空壳指向 `maintenance`。

## 四、各分组说明（面向用户，可直接做 UI 副标题）

- **外观**：主题、字号、强调色与动效——只改呈现，不动数据。
- **通知与桌面**：任务完成怎么提醒、托盘行为与免打扰时段。
- **模型与接口**（核心）：选模型、配 API 渠道与 Key；能力渠道（识图/搜索/OCR）折叠按需展开。
- **联网与代理**：出网代理、自签证书与联网检索授权——默认关闭，按需开启。
- **用量与资源**：花了多少、缓存占用与本机资源状态。
- **更新与备份**：检查更新、反馈问题；配置导入/备份与诊断日志折叠收起。
- **快捷键**：命令键位与冲突检测。
- **治理与决策**（高级）：Agent 规则、工具审批、决策阈值与审计记录——日常无需改动。
- **推理档位**（高级）：思考强度与各协议的映射参数。
- **运行时与诊断**（高级）：本地服务、运行时状态与日志——排障用。
- **实验特性**（高级）：尚未定型的开关，默认关闭。
