# 设置页信息架构精简设计（IA Simplification Design · 激进版）

> 性质：规划产物（设计材料）——**本文件不含代码实现**；输出调整后的设置项清单与分组说明，供用户裁决后另立 UI 工作包实施。
> 日期：2026-11-16（v2 激进版，替换 v1"保留 13→11"方案）。
> 触发：用户「保留的太多了」「联网与代理默认是开启的」「快捷键不需要实际上用不到」「新版本发布推送更新会自动在页面上出现更好，目前在设置内部不实用」「看看 reference 中怎么做的，学习优秀设计」。
> 现状基线：`DesktopSettingsPanel/types.ts` 的 `SETTINGS_SECTIONS`（13 组，9 core + 4 advanced，BLOCK-424 分层）；主组件 + `sections/` 40+ 面板。
> 蓝图对齐：BLOCK-454（adapter 设置）落点；G0 纪律不改。

## 一、对标学习（来自 `D:\1.WorkDir\reference\`，代码/文档实证）

| 产品 | 设置哲学 | 可借鉴点 | 不照搬点 |
|---|---|---|---|
| **codex** | 极简：整个协作设置只有 3 字段（`Settings.ts` = `model` / `reasoning_effort` / `developer_instructions`，7 行生成代码） | 核心设置就该极少；其余靠默认值与约定 | 它是 CLI/IDE 插件，无桌面全功能面，Petri 有本机 runtime/治理/数据，不能砍到 3 项 |
| **orca** | 18 个 pane（General/Appearance/Git/Terminal/Agents/Browser/…/Shortcuts/Experimental），靠 `Cmd-,` + **全局设置搜索** 解决查找 | ① 低频项不占导航焦点，靠搜索可达；② **更新 = 页面内 `UpdateCard.tsx`**（store 读 `updateStatus`，可折叠/关闭/带 changelog/状态动画），不在设置里让用户点检查；③ 键位有 pane 但不显眼 | 18 pane 对 Petri 过多；orca 的浏览器/Git/worktree 专属 pane 非 Petri 场景 |
| **ZCode** | Provider 设置自动保存 + 智能配置 + 个人草稿/推荐基线分离（`docs/.../settings.md`） | 模型/渠道设置自动保存、减少保存动作；复杂配置折叠到"高级" | 它的 provider registry 复杂度超出当前需要 |

**对标结论**：Petri 应从 codex 学"核心极少"，从 orca 学"全局搜索兜底 + 更新页面内卡片"，不学 orca 的 pane 数量。

## 二、用户三条裁决（高于对标，直接执行）

1. **联网与代理**：用户判"默认开启、不该占显眼位置" → 从 core 导航移除；能力保持（联网检索默认形态由后端策略决定，本轮不改产品行为），仅把它降为「高级」里的按需项，且不在核心首屏出现。
2. **快捷键**：用户判"实际用不到" → 从 core 导航移除，进「高级」折叠；不删除功能（保留可查找）。
3. **更新推送**：用户判"应在页面上自动出现，设置内部不实用" → 新增**页面内更新卡片**（对齐 orca `UpdateCard` 形态），更新入口从「隐私与维护」主位移除；复用已有 `useAutoUpdate`（BLOCK-452/453）+ `app:notify`，新增轻量页面卡片，不引入新框架。

## 三、调整后的分组清单（13 → 6 组）

> 稳定性：保留 6 个核心 id（深链兼容），其余 7 组降级为搜索可达的"高级子项"——**不是删除功能**，是从左栏主导航移入搜索/高级折叠。这与 orca「pane 多但靠搜索」相反：Petri 选更激进的"导航极少 + 搜索兜底"。

### 左栏导航（core，5 组，用户日常真正会点的）

| # | 分组(id) | 名称 | 说明（UI 副标题） | 内部设置项 |
|---|---|---|---|---|
| 1 | `models` | 模型与接口 ⭐ | 模型、API Key 与能力渠道 | 默认模型 / 生成偏好 / API Endpoint（URL·Key·模型·上下文）；折叠「能力渠道」（BLOCK-454：识图·搜索·OCR）；折叠「自动容错」 |
| 2 | `appearance` | 外观 | 主题、字号与强调色 | 主题、字号、主题色、动效（保持） |
| 3 | `desktop` | 通知与桌面 | 提醒、托盘与免打扰 | 通知、托盘、免打扰、关窗行为 |
| 4 | `usage` | 用量与资源 | 成本、缓存与本机状态 | 成本、缓存、机器状态；决策用量折叠 |
| 5 | `maintenance` | 数据与维护 | 数据目录、备份与反馈 | 数据管理、配置导入/备份（合并原 general + ConfigTransferPanel）、诊断日志、反馈；**更新检查移出→页面内卡片** |

### 左栏导航（advanced，1 个折叠组「高级」，内部子项搜索可达）

| 子项(原 id) | 名称 | 说明 |
|---|---|---|
| `decisions` | 治理与决策 | Agent 规则、工具审批、决策阈值、审计记录（内部再分三折叠） |
| `reasoning` | 推理档位 | 思考强度与协议映射 |
| `network` | 联网与代理 | 代理、证书、联网检索授权（默认态，按需才进） |
| `compute` | 远程与计算 | 远程目标(SSH)、Harness 环境 |
| `keymap` | 快捷键 | 命令键位与冲突（不常用，搜索可达） |
| `diagnostics` | 运行时与诊断 | 服务、运行时、日志 |
| `experimental` | 实验特性 | 未定型开关 |

> 高级组默认收起；用户 Cmd+,（或设置内搜索框）输入关键词直接定位到任一子项——借鉴 orca 的全局设置搜索，但 Petri 用更少的可见导航。

## 四、更新推送的新落点（页面内卡片）

- **形态**：复用 `useAutoUpdate` 的 `status`，在主界面（建议主窗右下/侧栏顶部，与通知卡 `NotificationCardStack` 同族）渲染轻量 `UpdateCard`：版本、"发现新版本"、[下载更新] / [稍后] / [关闭]，可折叠；下载后沿用现有 DMG/NSIS 流程。
- **设置页变化**：`maintenance` 中的 `UpdateChecker`（手动检查）移除主位，只在高级子项保留"更新偏好"（是否自动检查/通知开关）——因为用户判"设置内部不实用"。
- **边界**：不新引入 IPC（`notify`/auto-update 已有），不替换本地治理链；G0 本机试用形态，公证/签名不外推。

## 五、各分组说明（面向用户，可直接做 UI 副标题）

- **模型与接口**（核心）：选模型、配 API 渠道与 Key；识图/搜索/OCR 等能力渠道折叠按需展开。
- **外观**：主题、字号、强调色与动效——只改呈现，不动数据。
- **通知与桌面**：任务完成怎么提醒、托盘行为与免打扰时段。
- **用量与资源**：花了多少、缓存占用与本机资源状态。
- **数据与维护**：数据目录、配置导入/备份、诊断与反馈；更新会在界面上主动提示，不用进这里找。
- **高级**（折叠）：治理/推理/联网/远程/快捷键/诊断/实验——按需搜索进入，日常无需展开。
