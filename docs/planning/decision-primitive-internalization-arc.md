## 0. 终态愿景（一句话）

**代码拥有工作流，模型提供可编程常识**——格物里每一处"需要判断的地方"，都先过分类学判定：确定性判断留在代码，生成判断交给大模型，原子闭集判断走统一的**决策原语**（原子问题 → 校准概率 → 阈值门控 → 必有降级），复合判断拆成原子组合。决策原语的可换供给（云 Jev / 本地模型 / 拒绝出站）是平台能力，不是某个功能的私有实现。

## 1. 判断点分类学（内化的思想内核）

任何新功能涉及"模型判断"时，先过这四型判定（设计评审的固定问题）：

| 型 | 特征 | 归宿 | 本仓示例 |
| --- | --- | --- | --- |
| **A 确定性判断** | 规则可穷举、零语义模糊（状态机、字段比对、白名单） | **永远代码**，禁止模型化 | loop 决策（`loop-orchestrator.js:475`）、执行策略（`agent-execution-policy.js:25`）、verify_state（`verify-dispatch.js`）、敏感路径（`agent-tool-policy.js:108`） |
| **B 生成型** | 输出是自由文本/代码/结构化创作 | 大模型生成链路，**决策原语不碰** | 结果解读（`interpret.js` callDeepSeekSimple）、auto-title、agent 主循环 |
| **C 原子闭集判断** | 有限选项里选一/评分/是非，几秒内可判定 | **决策原语候选**（走 W1+ 逐点立项） | 话题漂移（`conversations.js`）、检索相关性（`knowledge-space.js`）、工具路由、marker→细胞类型（`interpret.js:19`） |
| **D 复合判断** | 多因素加权、多跳 | **拆成 C 的组合**，权重在代码（composite-scoring 模式） | 简历评分类场景（暂无，预留） |

**判定流程**：新判断点 → 先问"能不能写成 A 型规则"（能则写规则，结束）→ 再问"输出是否生成性"（是则 B 型，结束）→ 剩下的 C/D 型进入决策原语管线：`候选池登记 → 校准 PoC → A/B 对账 → 立项上线/诚实放弃`。

## 2. 五波内化路线（每波有独立的启动门与证据门）

### W0 — 地基与 PoC（= BLOCK-110，已立项 planned 排队）
wrapper（`decision-api.js`）+ 降级契约 + 中文校准 harness + 话题漂移直替 + 知识库二跳（+P3 选做工具预路由）。
**开门条件**：BLOCK-109 P2 收口 + 用户确认。**证据门**：中文 accuracy A/B 过关；失败则按 BLOCK-110 §4 收缩语义关闭，本弧线回到候选池（本文档保留，W1+ 全部冻结）。

### W1 — 已验证模式的横向复制（BLOCK-110 收口后，逐点立项）
候选队列（次序按 BLOCK-110 研究文档 §6.1 排序，每点独立 PoC 门，不打包）：
1. **marker→细胞类型判别**（`interpret.js:19` 规则表降级为候选生成器，Jev/决策原语补概率与置信度）——科学价值最高；
2. **copilot 发送前意图路由**（闲聊/任务/检索分流，`conversationRunStore` 发送链后端侧挂钩）——新增能力；
3. **工具两跳预路由**（若 BLOCK-110 P3 未做；依赖 BLOCK-109 P2 工具元数据交付，吃其族级分组）；
4. **测试失败归因分类器**（2026-09-21 用户提出测试耗时长/卡住问题后登记）：收口对账时自动分类「新回归 / 在册存量 / 环境 / flaky」——输入=失败签名+报错摘要+在册已知失败条目，确定性指纹先行、决策原语只接语义残差，低置信转人工；先例=BLOCK-104 归因矩阵（33/36）、test:changed 85/89 中「4 红在册」人工判读。开发者侧接点，不碰用户数据，出站顾虑最小，且是决策原语自身的第一份dogfood；
5. **增量式测试选择建议**（同日登记，谨慎档）：静态 `test/impact-map.json` 保持下限（fail-closed 红线不动），决策原语**只加不减**——额外建议本次改动可能波及的定向测试，误报代价=多跑一个测试，漏报不存在。

> 同日澄清（A 型划界）：测试「卡住」的根治是纯工程手段——每测试/flow 看门狗超时+超时 dump 进程树与句柄、flow 全局时间预算、句柄泄漏审计（本仓已确诊根因：block88 未关句柄、双端孤儿进程互毒窗口；BLOCK-102 已做 force-exit+timeout 加固）。**禁止用模型判断"是否卡住"**——超时器 0ms/0 成本/永不误判，属 A 型。
**开门条件**：W0 证据门绿 + 用户对每点单独裁决。**证据门**：同 W0 标准（≥100 样本校准 + A/B 对账 + 降级测试）。

### W2 — 平台化：决策原语成为一等公民（W1 复制 ≥2 点后评估立项）（**2026-09-22 状态更新：W2 前四件已随 BLOCK-116-DECISION-PLATFORM 当日收口**——决策台账 decision_log（migration 011，meta {point,threshold} 咽喉记账）+ 阈值配置中心 v1（decision-thresholds.js 七接点集中声明+证据绑定，热调留后续）+ 校准工具化 v1（calibration-common.mjs 共享库，touch-and-migrate）+ 观测面（GET /api/ai/decisions/summary + 设置面板 DecisionUsagePanel）；closeout 十门全绿 + flow 5/5。启动裁决=用户「你能做就做下去 不要让我裁决 你可以判断的」授予自主判断权。）
把"每个接点各自实现"收敛为统一决策服务，目标形态：
- **决策台账**：SQLite additive `decision_log` 表（对齐 `ai_usage` 先例）：decision_id / 接点名 / state 摘要（hash+截断）/ answers+probabilities+confidence / 阈值版本 / provider+model 版本 / latency / **degraded 标志**——任何一次路由可回放"当时为什么这么判"；
- **阈值配置中心**：每接点阈值（双阈值三区间等）服务端集中配置、版本化，与校准证据版本绑定（jev 升级→阈值必须重校准的机制化）；
- **校准工具化**：`scripts/calibrate-<point>.mjs` + 标注样本目录（JSONL）→ 自动产出 confidence-accuracy 报告（acceptance 风格 JSON），新接点接入成本从"手搓"降为"填样本"；
- **观测面**：设置页用量面板扩决策调用量/延迟/降级率（BLOCK-79 provider 速率面板同款模式）；
- **（候选）agent 可见决策工具**：把决策原语暴露为 MCP 工具供 agent 自用（如工具路由自问），是否暴露、暴露给谁另行裁决。
**开门条件**：W1 至少 2 点在生产路径稳定运行 + 用户裁决立项。

### W3 — 供给多样化与数据分级路由（与 W2 可并行评估）
决策原语的 provider 从"仅云 Jev"扩为矩阵，按 D-A 数据分级自动路由：

| 数据级 | 供给 | 说明 |
| --- | --- | --- |
| 一般（对话摘要级判断） | 云 Jev（`jev-1.13.0` pin） | 现状路径 |
| 敏感（含用户文档/未发表数据片段） | **本地供给**或拒绝出站 | 本地候选：①Jev 开源权重（若发布，未宣布）②本地小 LLM 结构化输出近似—— riding on 既有本地推理设施（model-gateway 已支持 Ollama/LM Studio/vLLM 可移植形状） |
| 高敏 | 该判断点不上模型 | A 型规则化或干脆不做 |

**开门条件**：存在真实的敏感数据接点需求（P2 类链路上线后自然出现）+ 本地近似供给的校准数据达标。**前置**：BLOCK-110 P0 D-A（数据分级表）、D-B（provider 可替换性）两项裁决已落地——本 Wave 是这两项的兑现处。

### W4 — 工程制度内化（模式写进家法，随 W1/W2 收口逐步做）
- **设计评审清单**：`$gewu-dev-infra` 增「判断点分类学 checklist」（本文 §1 四型判定 + 判定流程），新功能评审固定过一遍；
- **AGENTS.md 新增功能检查清单**增一行：`新增模型判断点 → 先过 A/B/C/D 分类 → C/D 型必须走决策原语 wrapper + 校准证据在册，禁止绕过 wrapper 直连`；
- **门禁**：决策契约测试模板进 dev-infra templates（降级路径/响应校验/阈值门控三件套）；决策接点的验收必须含校准 JSON（无证据不 verified）；
- **反模式红线**（写进 checklist）：禁止把 A 型规则模型化（"回退冲动"）；禁止 Jev 用于生成；禁止无校准证据上线；禁止跳过 wrapper 直连 API；禁止跨题型搬阈值（noul 与 Choice 概率不可比，jev-1.13 短板 §3.8）；
- **cookbook 内化**：把 typesafe 17 篇 cookbook 中与格物相关的模式（intent-routing / classifying_rag_passages / skill_suggestion / function_calling / rerank）改写为仓内参考案例（自写，非逐字移植，BLOCK-104 外部方法论内化批同款姿势）。

## 3. 全程不变的约束（贯穿所有 Wave）

1. **单工作包串行**：任一 Wave 启动都占 active 槽位，走完整立项；
2. **A 型判断永不模型化**：规则清单是契约，维护一份「确定性判断登记表」作为反模型化防线（W2 平台化时随 decision_log 一并建）；
3. **生成链路零迁移**：B 型永远是大模型地盘；
4. **降级必有**：任何决策接点缺 key/超时/校验失败/阈值未配置，一律回退 W0 之前的现行为；
5. **数据出站服从 D-A 分级表**（BLOCK-110 P0 裁决产物），本地供给就绪前敏感链路不接；
6. **G0 纪律**：不外推 packaged/Provider/GA；本弧线全部属于产品内工程能力。
