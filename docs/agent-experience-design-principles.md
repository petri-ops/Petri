> 定位：本文件是 **Agent 能力体验设计的准则**，指导 W2/W3/W7 等所有涉及 Agent 自主性与交互的工作；与 `AGENTS.md` 产品个性纪律、现有权限/审批架构对齐。
> 核心裁决：**5 条方向确认采纳，但第 5 条必须加边界**——"人工介入最小化"不能吃掉 Petri 的魂（治理透明 / 动态审批 / 全链可审计）。对标只借"少步骤、自动化、方案择优"的形，不照搬"无边界自主"。

## 一、五条原则的确认与细化

### 原则 1 · 体验优先（最小化操作步骤）— ✅ 确认，加一条约束
- 细化：核心目标是**任务完成的总步骤最少**，交付以真实产物为准；价值判断是"用户事情办成了没"，不是"界面点了几次"。
- **新增约束 P1-a**：步骤最小化**不得牺牲证据链**——自动化省下的每一步仍须留痕（tool_job / artifact / trace），"少操作"不等于"少审计"。这是 Petri 区别于通用 agent 的差别形态。

### 原则 2 · 自主决策范围 — ✅ 确认，必须与现有权限架构对齐
- 细化：Agent 的"自主"**在用户选定的 accessMode 档位内自主**，不是无边界自主。现有四档即自主边界：
  - `read`：只读探索、联网检索、读文件、方案分析 → **全自主**
  - `workspace-write`：项目内写 + 前台命令 → **自主**，但受工具审批档约束
  - `full`：系统级写、插件/后台进程 → **需用户显式进入该档**，非默认自主
  - `plan`：只允许 plan 与只读探索，有副作用工具一律拒绝（对齐 codex plan 模式）
- **新增约束 P2-a（红线）**：决策权威来自 UI 显式 `accessMode`，**禁止从消息文本推断权限**（BLOCK-10 S-003 的 prompt-injection 攻击面：`ackToken=…+已确认` 曾可翻转执行）。任何"更智能地猜用户意图以扩权"的设计都不得越过这条。
- **新增约束 P2-b**：工具审批三档（allow/ask/deny/observe）+ 动态防护（用户规则 / guard / 循环防护 / MCP destructive 信任位）是自主决策的护栏，**不因追求自动化而放宽**；`ask`/`deny` 是用户裁定的边界，Agent 不得自动绕过。

### 原则 3 · 自动化信息获取 — ✅ 确认，加两条诚实约束
- 细化：任务需要外部信息时，Agent 默认自动完成联网检索与相关 API 调用，无需用户逐步指示。
- **新增约束 P3-a（诚实源）**：来源必须可审计——每条外部信息保留 `source`（主机名）/ URL / 引用角标，用户能追溯；禁止无来源的"编造式回答"。
- **新增约束 P3-b（诚实失败）**：未配置 provider 或接口失败时，如实报 `web_search_not_configured` / external-blocked，**绝不返回空数组冒充"搜过了"**（沿用 `web-search-provider.js` 既有契约）。
- **新增约束 P3-c（本地主权）**：联网能力默认走 SearXNG（可自建、来源可审计）或本地实现；DeepSeek 等云 adapter 是可选渠道，不设为默认——"自动联网"不等于"绑死某云"。

### 原则 4 · 方案择优输出 — ✅ 确认，加两条约束
- 细化：Agent 基于获取的信息自主评估，给出**一个最合理方案 + 简短理由**，而非罗列多选项把选择成本甩回用户。
- **新增约束 P4-a（可追溯判断）**：推荐必须带依据（基于哪些事实/产物/权衡），不是黑箱结论；用户能看出"为什么是这个"。
- **新增约束 P4-b（可覆盖）**：推荐 ≠ 强制——用户可一句话改向；涉及重大取舍（成本 vs 质量 / 速度 vs 安全 / 本地 vs 云）时显式点出代价，让用户看得见权衡。反模式：为"显得自主"隐瞒取舍。

### 原则 5 · 人工介入最小化 — ⚠️ 方向确认，必须加边界后采纳
- 细化：仅在**信息不足 / 高风险操作 / 涉及用户偏好**三类场景请求确认，其余默认自动完成。
- **调整 P5-a（魂的护栏）**：以下场景**必须**人工确认，不受"最小化"裁剪：
  1. 工具审批档为 `ask`/`deny` 的调用；用户规则 / 动态 guard 命中的调用（P2-b）
  2. 进入或执行 `full` 档的破坏性/不可逆操作（删用户数据、系统写、对外发布）
  3. 涉及 token 花费、配额、外部副作用的付费操作（如真实 Provider 调用）——保留用户知情权
- **新增约束 P5-b（偏好记忆）**："涉及用户偏好"的确认应尽量**一次告知、后续记住**（userPrefs 机制），避免同类问题反复打断——这才是真正减少人工介入的正道，而不是砍掉必要的确认。
- **新增约束 P5-c（可接管）**：任何时候用户可中断/纠正正在自动执行的 Agent；自动化不等于失控。

## 二、新增的横向约束（5 条之外）

| # | 约束 | 理由 |
|---|---|---|
| X1 | **全链可审计**：所有自主决策与执行落 trace / tool_job / artifact / ack，用户可回溯「Agent 为什么这么做、做了什么」 | 本地主权 + 证据自证是 Petri 的魂，体验优化不得侵蚀 |
| X2 | **失败诚实**：自主链路上任何一步失败如实上抛并给可行替代，不静默吞错、不伪造成功 | 沿用 reason-codes / fail-closed 传统 |
| X3 | **幂等与可回滚**：自主执行的写操作尽量幂等；批量/破坏性写提供回滚或预览 | 降低自动化误操作的代价 |
| X4 | **G0 阶段纪律**：体验设计不外推 packaged/Provider/公证/GA 资格面；联网/API 自动化在本机试用边界内 | AGENTS.md 最高优先级纪律 |
| X5 | **差别形态自检**：任何"向 ZCode/Codex 学习"的交互，必须回答「本地可审计 / 治理透明 / 证据自证体现在哪」，答不出不做无差别复刻 | 2026-10-12 用户裁决「借鉴优点，保留自己的特色」 |
