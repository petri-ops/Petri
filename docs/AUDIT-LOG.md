## 广播规则

- 🔴：阻塞当前验收，主 Agent 必须优先处理。
- 🟢：已有独立提交且可安全合并，主 Agent 必须先核对。
- 🟡：建议或待评估，不阻塞当前工作。
- 🔵：当前唯一进行中阶段。
- ✅ 完成事项只在“最近处理记录”保留一个紧凑条目；详细证据进入 canonical 计划、Acceptance 或归档。
- 不在本文件保存凭据、用户数据、绝对结果路径或隐藏推理过程。

- **滚动归档触发（硬性）**：活跃文件 > 50KB，或处理记录最早条目日期跨月——满足任一，下次会话启动必须先归档再开始主线：把已完成/已销号旧记录与「最后更新」累积原文按区块原文剪切到 `docs/archive/checkpoints/audit-log-through-<最早保留日前一天>.md`（带来源声明），活跃台只留 头部 + 「最后更新」（仅最近一条）+ 当前待处理项 + 每包最新一条记录 + 最近 5 条销号 + 本规则。归档剪行后必须跑 `npm run docs:check`：凡 registry `entrypoint` 指向本台的 canonical 文档，其直链必须常驻头部「入口直链」行，不得只随旧记录进归档。
- **行写入纪律**：处理记录每行 ≤ 3 行（约 600 字符）：一句话结论 + 用户裁决原话/关键数字 + canonical 文档指针；阶段切片与长篇证据进工作包 plan/closeout 文档；「最后更新」行只描述最近一次更新，旧累积随归档走，不在行尾追加历史条目。
