# coding-playbook — 编码实战手册

通用编码任务的实战守则（产品内置 skill，服务格物工作台里的编码场景）。

## 用途

agent 在接到编码任务（修 bug / 实现功能 / 重构）时，通过 skill 元工具获取本守则并全程遵循。守则覆盖六条纪律：

1. **项目约定优先**——先读 README / 配置 / 邻近代码，跟随既有风格。
2. **先读后改**——改前读目标文件与调用方/测试；删除改签名前查引用面（配合 `codegraph_who_imports` / `codegraph_classify_edges` 工具）。
3. **小步最小改动**——只改任务相关行，不顺手重构。
4. **验证闭环**——改完跑项目真实测试，宣称「通过」必须有真实执行证据。
5. **诚实汇报**——失败贴原文、未验证就说明、盲区不猜测。
6. **依赖默认不加**——新增第三方依赖先征求确认。

## 使用方式

- agent 侧：`skill_discover`（发现）→ `skill_get`（取守则全文）→ 在任务中遵循。
- 无插件依赖（`plugins.required: []`），纯提示守则形态，不触发插件可用性检查。

## 血统与边界

- 素材改编自开发侧 harness 纪律（HK-01 红绿先行 / HK-02 YAGNI 最小化的产品回声，见 `docs/pending-work-backlog.md` 候选池 C-18/C-19），**内化重写而非复制** `.agents` 资产——两轨不混红线（BLOCK-124 plan §1）。
- v0.1.0 边界：守则靠 agent 主动获取（skill 元工具），**不做**系统级强制注入（每个编码任务自动携带）——自动注入的时机与 token 成本留观察（C-19 续观项）。
