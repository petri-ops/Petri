## 适用场景

有两/groups 以上条件、每条件 ≥3 生物学重复的 RNA-seq 计数矩阵 → 差异表达基因清单。
领域惯例以**计数矩阵**（raw counts）为输入——TPM/FPKM 会破坏 DESeq2 的分布假设
（见步骤 1 的领域含义）。

## 参考路线（按典型数据实情排列，可跳步/换序并说明理由）

### 1. 数据导入与质检前置

- 惯例做法：读入 counts 矩阵与 coldata（样本元数据表），核对行列对齐、重复数、条件设计。
- 为什么通常这么做：DESeq2 的统计模型假设 counts 服从负二项分布，任何上游（比对/定量）
  换工具都要重算 counts；coldata 的每一列都是潜在 design 变量，缺列后面无法补救。
- 本数据下是否适用：矩阵行列名与 coldata 样本名对得上、每条件有足够重复数时自然适用；
  数据本身已 cleaned 时可合并进后续步骤。
- 常见坑：用 TPM/FPKM/已归一化矩阵喂 DESeq2（模型假设直接被破坏）；样本名大小写/空格导致静默错位。
- 依据: bioconductor-deseq2

### 2. 预过滤（pre-filtering，可跳过）

- 惯例做法：去掉几乎所有样本中 counts 近零的基因。
- 为什么通常这么做：不影响模型正确性，只省内存/多重检验负担；这是「卫生」步骤不是统计步骤。
- 何时偏离：小规模数据可整个跳过；跳过时在报告说明「未预过滤」即可。
- 常见坑：过滤规则没写进报告（读者无法复现）；误以为过滤能「改善 p 值」。
- 依据: bioconductor-deseq2

### 3. 设计公式（design formula）选择

- 惯例做法：`design = ~ batch + condition`——把关心的变量放最后，已知批次/混杂变量放前面。
- 为什么通常这么做：DESeq2 按 design 里的顺序做边际化；批次在前 = 在 condition 检验里
  扣除批次效应。
- 判断要点：数据里确实存在批次/混杂时这样设计；没有批次变量就不放（硬造一个反而是噪音）。
  配对数据保留配对信息。
- 常见坑：把 batch 放在 condition 之后（等于没校正）；把配对信息丢掉（paired design 当
  unpaired 做）；变量名与 coldata 列名拼错导致因子被静默忽略。
- 依据: bioconductor-deseq2
- 依据: deseq2-paper

### 4. 估计与检验（DESeq → results）

- 惯例做法：`DESeq(dds)` 一步完成离散度估计、原始 LFC 估计、Wald 检验；
  `results(dds, contrast=...)` 提取指定对比。
- 为什么通常这么做：Wald 检验是默认；对比的参考/处理方向决定 log2FC 符号——方向搞反是
  报告级事故，所以惯例强调显式声明。
- 判断要点：数据实情特殊时（如无对照只有组间比较），对比方式可与惯例不同，但方向
  语义要在报告里讲清楚。
- 常见坑：contrast 方向写反（上调/下调全反）；对照因子水平默认按字母序（Control 恰好在前
  是运气不是设计）。
- 依据: bioconductor-deseq2

### 5. LFC 收缩（lfcShrink）

- 惯例做法：对低表达/高离散基因的 log2FC 做收缩（apeglm 默认），用于**排序与可视化**。
- 为什么通常这么做：收缩改善 LFC 估计的稳定性，但不改变 p/padj——DE 判定仍以未收缩
  results 为准。
- 判断要点：展示层惯例；跳过不影响 DE 判定本身。
- 常见坑：用收缩后 LFC 的阈值筛基因并宣称「显著」（混入未过检验的基因）。
- 依据: bioconductor-deseq2

### 6. 多重检验与阈值（independent filtering + FDR）

- 惯例做法：以 `padj < 0.1`（FDR, Benjamini-Hochberg + 独立过滤）为默认显著阈值。
- 为什么通常这么做：Genome-wide 检验必须校正多重性；0.1 是 DESeq2 社区惯例默认，
  0.05 更严——阈值是领域约定不是数学真理，报告写明用了哪个即可。
- 判断要点：研究目的更严/更宽时可换阈值，报告写明数值与理由就是合格做法。
- 常见坑：拿 raw p-value 阈值（p<0.05）当显著基因清单；不报告 up/down 各多少。
- 依据: bioconductor-deseq2
- 依据: deseq2-paper

### 7. 可视化与报告

- 惯例做法：PCA（用 vst/rlog 变换，不用 raw counts）、MA plot、volcano、top 基因热图。
- 为什么通常这么做：PCA 是样本级 QC——有样本离群要先解释再谈 DE；MA/volcano 的
  坐标轴是领域通识语言。
- 判断要点：图表种类按数据故事需要取舍；轴标签/单位/变换注明是可读性惯例。
- 常见坑：对 raw counts 直接做 PCA（方差被高表达基因绑架）；热图用未聚类的任意基因子集
  却宣称「全局模式」。
- 依据: bioconductor-deseq2

### 8. 结论谨慎度

- 惯例做法：结论按证据等级分层表述——「padj<0.1 且 |LFC|≥1 的 N 个基因」是数据结论；
  通路解释是解释性推断，标注为推断。
- 为什么通常这么做：差异分析回答「哪些基因在该对比下有统计证据」，不回答「为什么」；
  机制解释需要正交证据。
- 判断要点：负结果如实报告（「在该检验力下未检出」而非「没有差异」）；推断句注明
  「推断，需正交验证」是惯例措辞。
- 常见坑：把统计显著直接等同生物学重要；用单次未重复实验断言机制。
- 依据: deseq2-paper

## 常见坑速查（知识速查，非检查表）

| 现象 | 为什么是坑 | 惯例姿势（参考） |
| --- | --- | --- |
| TPM/FPKM 喂 DESeq2 | 分布假设破坏，padj 无意义 | raw counts + DESeq2 内部归一化 |
| batch 放 design 末尾 | 批次效应混入 condition | `~ batch + condition` |
| contrast 方向反 | 全报告上调/下调颠倒 | 显式声明 ref/treatment 并复核 LFC 符号 |
| raw p 阈值筛基因 | 假阳性不可控 | padj（FDR）阈值 + 写明数值 |
| 收缩 LFC 做 DE 判定 | 混入未过检验基因 | 判定用 results()，收缩仅展示 |
| 重复数 <3 | 检验力不足，估计不稳 | 每条件 ≥3 生物学重复，不足时如实降级结论 |

## 惯例校准点（参考——用于对照产出质量的感觉，不是逐项打勾的验收清单）

agent 产出后可对照这些惯例感觉校准（偏离任何一条并说明理由，都是合格做法）：

- 输入惯例是 raw counts（TPM/FPKM/归一化矩阵会破坏分布假设）
- design 公式惯例显式写出，批次变量惯例在 condition 前
- contrast ref/treatment 惯例显式声明
- 显著性阈值惯例写明（padj + 数值），up/down 分计数惯例报告
- PCA 惯例用 vst/rlog 变换并注明
- 结论惯例分层：数据结论与推断分开，推断句带标注
